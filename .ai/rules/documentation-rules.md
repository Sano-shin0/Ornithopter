# Documentation Rules

## 1. Purpose

These rules ensure that ORNITHOPTER documentation remains understandable, traceable, reproducible, and maintainable.

---

## 2. Language

Technical documentation should primarily be written in English unless project communication explicitly requires another language.

---

## 3. Document Purpose

Every document should have a clear purpose.

Avoid documents that mix unrelated subjects.

---

## 4. Standard Structure

Where applicable, engineering documents should contain:

1. Purpose
2. Scope
3. Inputs
4. Assumptions
5. Method
6. Results
7. Discussion
8. Limitations
9. Conclusion
10. References
11. Next Actions

---

## 5. Terminology

Use consistent terminology throughout the repository.

If a technical term is ambiguous, define it.

Do not use multiple names for the same engineering parameter without explanation.

---

## 6. Figures and Tables

Figures and tables must have:

* descriptive titles,
* units,
* legends where necessary,
* traceable data sources.

A figure must not be the only place where an important numerical value exists.

---

## 7. References

External information must be referenced.

References should allow another engineer to locate the original source.

---

## 8. Decision Documentation

Important design decisions must explain:

* problem,
* alternatives,
* criteria,
* analysis,
* selected option,
* justification,
* consequences,
* unresolved uncertainty.

---

## 9. Status

Documents should make their maturity clear.

Recommended statuses:

* DRAFT
* REVIEW
* ACCEPTED
* SUPERSEDED
* ARCHIVED

---

## 10. Changes

Important changes must be documented.

Do not silently rewrite historical engineering conclusions.

If a conclusion changes, explain:

* what changed,
* why it changed,
* what evidence caused the change,
* which downstream documents are affected.

---

## 11. Reproducibility

Another engineer should be able to understand how an important result was obtained without depending on private conversation history.

---

## 12. Forbidden Behavior

Do not:

* remove contradictory evidence,
* rewrite history without explanation,
* hide assumptions,
* remove failed experiments,
* delete important negative results,
* or present draft information as validated engineering knowledge.
